# RFC 9457 Problem Details for HTTP APIs

[RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) (obsoleting RFC 7807) defines a standard JSON format for conveying machine-readable error details from HTTP APIs.

All non-2xx error responses from a REST API should return `Content-Type: application/problem+json`.

---

## 1. Standard Fields

| Member | Type | Requirement | Description |
| :--- | :--- | :--- | :--- |
| `type` | URI string | Recommended | Absolute URI identifying the problem type (e.g. `https://api.example.com/errors/validation-failed`). Defaults to `about:blank`. |
| `title` | string | **Required** | Short, human-readable summary of the problem type. Should not change between occurrences of the same problem. |
| `status` | integer | **Required** | The HTTP status code generated by the origin server (`400`, `404`, `422`, etc.). |
| `detail` | string | Recommended | Human-readable explanation specific to this occurrence of the problem. |
| `instance` | URI string | Recommended | URI reference identifying the specific occurrence / resource where the error happened. |

---

## 2. Standard Schema Example (General Error)

```json
{
  "type": "https://api.example.com/errors/resource-not-found",
  "title": "Not Found",
  "status": 404,
  "detail": "Order with ID 'ord-88321' could not be found.",
  "instance": "/api/v1/orders/ord-88321"
}
```

---

## 3. Extension Member for Validation Errors (`invalid_params`)

When returning a `422 Unprocessable Content` response due to payload validation failure, provide an `invalid_params` array detailing each failing field:

```json
{
  "type": "https://api.example.com/errors/validation-failed",
  "title": "Unprocessable Content",
  "status": 422,
  "detail": "The request body failed schema validation.",
  "instance": "/api/v1/orders",
  "invalid_params": [
    {
      "name": "customer.email",
      "reason": "Must be a valid email address"
    },
    {
      "name": "items[0].quantity",
      "reason": "Quantity must be an integer greater than or equal to 1"
    }
  ]
}
```

---

## 4. OpenAPI 3.1 Schema Definition

Include this reusable component in the OpenAPI document:

```yaml
components:
  schemas:
    ProblemDetails:
      type: object
      description: RFC 9457 Problem Details error envelope.
      required:
        - title
        - status
      properties:
        type:
          type: string
          format: uri
          default: "about:blank"
          example: "https://api.example.com/errors/invalid-input"
        title:
          type: string
          example: "Invalid Request Body"
        status:
          type: integer
          example: 422
        detail:
          type: string
          example: "The request body failed schema validation."
        instance:
          type: string
          format: uri-reference
          example: "/api/v1/orders"
        invalid_params:
          type: array
          items:
            type: object
            required:
              - name
              - reason
            properties:
              name:
                type: string
                example: "email"
              reason:
                type: string
                example: "Must be a valid email address"
```
