# OpenAPI Specification 3.1 Architecture Guide

A technical reference for structuring OpenAPI Specification 3.1 documents in production.

---

## 1. Top-Level Document Structure

An OpenAPI 3.1 document consists of eight primary sections:

```yaml
openapi: 3.1.0
info:
  title: Enterprise Order API
  version: 1.0.0
  description: Production RESTful API conforming to OpenAPI 3.1 standards.
  contact:
    name: API Engineering Team
    email: api@example.com
  license:
    name: Apache 2.0
    url: https://www.apache.org/licenses/LICENSE-2.0.html

servers:
  - url: https://api.example.com/v1
    description: Production environment
  - url: https://staging-api.example.com/v1
    description: Staging environment

tags:
  - name: Orders
    description: Order placement, status tracking, and cancellation.

paths:
  # Endpoints mapped by path and HTTP method

components:
  # Reusable schemas, parameters, security schemes, and responses

security:
  # Global security requirements applied across all endpoints
```

---

## 2. Key Differences in OpenAPI 3.1 (vs 3.0)

1. **100% JSON Schema 2020-12 Compatibility**:
   - `type` can now be an array: `type: ["string", "null"]` replaces `nullable: true`.
   - Full support for `$schema`, `$defs`, `prefixItems`, `unevaluatedProperties`.
2. **Webhooks Support**:
   - Top-level `webhooks` key allows describing out-of-band events that your system dispatches to consumer endpoints.
3. **Mutual TLS and Extended OAuth Flows**:
   - Enhanced security schemes including `mutualTLS`.

---

## 3. Standard Security Schemes

Declare security definitions under `components.securitySchemes`:

```yaml
components:
  securitySchemes:
    # 1. Bearer JWT
    BearerAuth:
      type: http
      scheme: bearer
      bearerFormat: JWT
      description: Enter the JWT token generated by authentication service.

    # 2. API Key (Header)
    ApiKeyAuth:
      type: apiKey
      in: header
      name: X-API-Key
      description: API Secret Key for server-to-server integrations.

    # 3. OAuth2 Authorization Code
    OAuth2:
      type: oauth2
      flows:
        authorizationCode:
          authorizationUrl: https://auth.example.com/oauth/authorize
          tokenUrl: https://auth.example.com/oauth/token
          scopes:
            read:orders: Read order history
            write:orders: Create and update orders
```

Apply globally or override on individual operations:
```yaml
security:
  - BearerAuth: []
```
